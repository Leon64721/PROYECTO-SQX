## Definiciones de referencia

**Tipos de estrategia (`strategy_type`):**
- `_comment`: Eje 1: que tipo de logica de entrada/proposito tiene. Lista abierta -- agregar valores nuevos aqui cuando aparezca un tipo genuinamente distinto; no forzar algo en una categoria que no le calza.
- `breakout_session`: Rompimiento de rango de una sesion/ventana horaria fija (ej. ORB -- Opening Range Breakout)
- `trend_following`: Sigue una tendencia ya establecida (medias moviles, canales, momentum sostenido)
- `mean_reversion`: Apuesta a que el precio vuelve a un promedio/banda tras un extremo (RSI, bandas, desviacion)
- `ml_signal`: Usa una senal de machine learning como parte de la logica de entrada/salida (ej. QlibSignal/ONNX)
- `compliance_filter`: No es una senal de entrada en si -- es una regla de cumplimiento/restriccion (sesion horaria, noticias, trades por dia) que se AND-ea con una senal real (ej. PF_NYSessionWindow)
- `multi_timeframe`: Combina explicitamente mas de un timeframe/grafico como parte del criterio de entrada
- `other_unclassified`: No encaja claramente en ninguno de los anteriores todavia -- usar mientras se decide con el usuario, no dejar en null indefinidamente

**Estados (`status`):**
- `_comment`: Eje 2: vigencia. Se asigna con el usuario, nunca se infiere solo de la fecha de modificacion (un archivo viejo puede seguir siendo la base vigente de un proyecto activo).
- `vigente`: En uso activo / es la version de referencia actual de ese proyecto o estrategia
- `en_pruebas`: En desarrollo o validacion, todavia no se decidio si reemplaza a lo vigente
- `obsoleto`: Superado por una version mas nueva o descartado -- candidato a moverse a 05_ARCHIVO_DESCARTABLE (nunca se mueve/borra sin confirmar con el usuario)
- `pendiente_clasificar`: Recien detectado por scan_content.py, todavia sin revisar con el usuario -- estado inicial de todo item nuevo
